# Synthetic 4.0 eval corpora

Four opt-in corpora, generated from seed `40891` (generators in `corpus/synthetic-*.ts`, SHA-256 data fingerprint in each spec). Every document is fictional. No account, live brain or Cloudflare API is used: the loader uses the production index write path over local D1, exact-cosine Vectorize and the pinned local embedding model. Default runs (`npm run eval:recall -- --variant baseline`) still select `core-1k` and never include these.

## Reproduce

Install with `npm ci`. For each corpus ID in `temporal noise injection`:

```sh
npm run eval:recall -- prepare --variant baseline --corpus ID
npm run eval:recall -- --variant baseline --corpus ID
```

For `standing`, use `--variant no-rerank` and add `--max-neurons 6000` to `prepare` (the byte-count estimate is about 4,100 production-equivalent neurons; nothing is billed, embeddings are local). `prepare` records content-addressed embeddings in `.eval-cache/replay/<corpus>.*.jsonl`; the second command is fully offline. Caches are not committed, as for public corpora: only the core cache is committed by repo convention, and these corpora never read or write it. Add `--json PATH` for a machine-readable report. `temporal` also works with `--compare no-rerank,baseline --target knowledge-update` (Track 2's current-state gate) or `--target temporal-during` (Track 2's as-of gate, see below); `noise` with `--target noise` (a no-harm check only, see below); the gate's cost check stays inconclusive on the sqlite backend, as everywhere.

A gate needs at least 200 queries and 30 clusters and the corpus must contain the failure it is meant to catch. Meeting the query and cluster floor is not enough: a corpus is a gate only where a wrong change is shown to fail it and a right change is shown to pass it, which is why `temporal`'s gate role is split into three categories above rather than stated once for the whole corpus (round 3 found the unsplit `temporal` category let a deleted date parser pass at +0.243 MRR while the as-of subsets it exists to protect had not moved at all). `standing` is a threshold-selection gate, not a paired before/after gate: it has no baseline/candidate comparison, only a dev-chosen operating point scored on held-out data.

## temporal (GATE for `knowledge-update`; GATE for `temporal-during`; `temporal` category report-only; `control-not-asof` excluded pending T-0089.2.5)

What it measures. 120 timelines, each with a distinct pseudo-word subject ("Velmora studio lease", no numbered siblings), in four shapes: `update` (35), `retro` (35, backdated notes and a recap written after the fact), `retracted` (30, a fact later withdrawn by a correction), `edited` (20, a document edited after the as-of date). Each timeline gets a current-state question (category `knowledge-update`, gold = the fact valid now). Its past questions split across three categories:

- `temporal` (report-only, 240 queries): `prefiltered` ("Where was X in April?" with a per-query `asOf`; the runner passes `before: asOf + 1`, so the newer fact is excluded and this only tests ranking among older documents) and `phrase-dated` ("as of April 15, 2026", not pre-filtered, so the phrase parser is exercised). **Do not target this category.** Round 3 found it lets a deleted date parser pass at +0.243 MRR (all of it from `phrase-dated`, none from the as-of subsets below, which stayed flat at 0.529 to 0.529) because today's parser turns a date into a created-on-that-day filter that returns nothing, so `phrase-dated`'s baseline of 0 looks identical to a parser deleted entirely. In 115 of 120 `phrase-dated` queries tense wording alone ("was" vs "is now") already puts the old fact above the new one without any date parsing, so this subset cannot distinguish a correct as-of implementation from no implementation at all.
- `temporal-during` (**the gate**, 100 queries in 100 clusters, meeting the corpus test's power floor): `phrase-vague`, `backdated-past` and `retracted-past` ("during April / July", no pre-filter). `expectedAsOf` records the date for the oracle. Because none of these three subsets' phrasing matches any pattern the shipped parser recognizes (`src/text/temporal.ts`, out of scope here), this category's baseline is unaffected by the parser at all, which is exactly why deleting it leaves `temporal-during` flat while it moves `temporal`: the category split isolates the as-of signal from that confound. A plain recency reorder (newest document first) loses MRR here (a real re-scoring drops the category from 0.675 to 0.500, concentrated entirely in `backdated-past`, 1.000 to 0.500, interval entirely below 0) and the supersession oracle gains it (0.675 to 1.000); both directions are visible, which is what a gate needs (`temporal-gate.test.ts` re-scores the real corpus both ways and asserts the pass/fail split against `evaluateGate`).
- `control-not-asof` (30 questions naming a place such as "the Aug 8 ... Cafe"; correct behaviour is ordinary retrieval, unaffected by a date parser). **Excluded from gating**, tagged `gap:temporal-month-day-controls`, until T-0089.2.5 lands (see below).

Why `control-not-asof` is excluded rather than compared, and the ordering rule that ends it (T-0089.2.5). Today's shipped parser already misreads these month-day names as dates, so the baseline itself scores 0/0. A delta-from-baseline rule compares a candidate against that same 0, so a worse candidate parser cannot show as a regression: both score 0, and there is nothing left to fall to. Concretely, a parser that reads every month-day-shaped string as an as-of date gets 40% of these controls right (0.60 MRR) against a correct parser's 1.00, yet a delta-based rule still calls 0.60 an improvement over the 0 baseline (re-scored and asserted in `temporal-gate.test.ts`: the "misreading" candidate passes `--target-gaps temporal-month-day-controls` exactly as the "correct" one does). **The mechanical target-gaps rule alone cannot tell those two apart; do not change `gate.ts` to try.** Instead, the ordering is explicit: T-0089.2.5 (filed on the board, parent T-0089.2) must land first in Track 2, fixing the parser's month-day misreading. Its acceptance is manual, on top of the mechanical rule, and both parts must hold:
1. `npm run eval:recall -- --compare no-rerank,baseline --corpus temporal --target-gaps temporal-month-day-controls` reports a passing `improvement` rule for `gap:temporal-month-day-controls` (the mechanical part gate.ts already computes); and
2. the printed `gap:temporal-month-day-controls` row reaches **MRR@10 >= 0.95** (the absolute floor gate.ts cannot express from a delta alone; read it from the row gate.ts's own comparison prints, or from `--json`'s `results` filtered to that tag).

Only once both hold should the `gap:temporal-month-day-controls` tag be removed from the 30 control queries in `corpus/synthetic-temporal.ts`, at which point they rejoin the ordinary `temporal` category's regression rule (report-only, as above) and protect every later temporal change from the same class of misreading. `MONTH_DAY_CONTROL_GAP_TAG` and `MONTH_DAY_CONTROL_ACCEPTANCE_MRR` in `corpus/synthetic-temporal.ts` pin the tag string and the 0.95 floor; a corpus test and an acceptance test both check the doc, the tag and the constant agree, so the three cannot drift apart silently. A cheaper enforcement than reading the printed row by hand is possible without touching `gate.ts`: a small vitest test in this corpus that loads a recorded `--json` candidate report and asserts its `gap:temporal-month-day-controls` row's `mrr10` meets the floor before the tag is allowed to be removed. This round documents the idea but does not build it, since the tag has not been removed yet and there is no such report to check against.

Data model (`corpus/types.ts`). `CorpusEntry` gains `updatedAt`, `validFrom`, `validUntil`, `retractedAt`, `priorVersions`; supersession is a `supersedes` edge (newer to older). The loader writes `updated_at` and the edges today. `applySupportedTemporalMetadata` (`corpus/loader.ts`) writes `valid_from`/`valid_until` only when the entries table has those columns (none yet), and `loadCorpus` takes a `temporalMetadata` writer as the extension point for Track 2's write path. Queries gain `expectedAsOf`. Documents are dated at noon UTC so the local-time date parser gives the same answer in every timezone from UTC-11 to UTC+11.

`retracted-past` gold semantics, and an open Track 2 decision. "Where was X during July?" after a move to B was announced and later corrected as never having happened. The gold is `old` (A) only, grade 2: in reality nothing moved. An earlier draft also graded the announced move `bad` (B) as partially relevant (1), meant to reward a system aware of the belief held during the retracted window; round 3 found this let a system that ranks the cancelled move first score exactly as well as one that ranks the actually-true answer first, since `recallAtK` and `mrrAtK` both ignore grade and stop at the first gold id they see (proven in `temporal-gate.test.ts`: the same `[bad, old]` ranking scores MRR 1.0 under the old dual-grade gold and 0.5 under the current single gold). The validity data agrees with the current label: `bad` declares an empty window (`validUntil` equal to `validFrom`, half-open, never valid), meaning it was never actually true, while `retractedAt` still separately records when the correction was learned. Whether a shipped implementation should instead model "later retracted" as a status distinct from an empty `valid_until` window, and whether a belief-time question deserves partial credit through some mechanism other than a second gold id, are Track 2 decisions this corpus does not make; `synthetic-report.ts` prints how often the cancelled move still surfaces in the top 10 (today, 30 of 30 `retracted-past` queries) as a diagnostic, not as something a change is judged on.

Oracle (`temporal-oracle.ts`, printed in the report). From the recorded rankings alone it simulates (a) supersession applied: drop documents whose declared validity excludes the question date; (b) recency only: reorder by creation time, which the backdated recap defeats. Its query and cluster counts now match the headline (both exclude the known-gap controls; a round-3 finding was that they previously disagreed, "temporal n=370" against the headline's 340). This is an upper bound on what dropping invalid documents can do to today's ranking, not a prediction of Track 2's contradiction detector: the loader writes validity exactly as the corpus declares it, so the ceiling assumes perfect contradiction detection at capture, with no false positives or missed contradictions. Baseline current-state MRR@10 is 0.702; supersession applied 0.809 (the ceiling given what the pool returns); a plain recency reorder falls to 0.212. On `temporal-during`, supersession applied 0.456 to 0.995 MRR; recency-only falls to 0.178. Per subset: `backdated-past` 0.514 to 1.000 (recency falls to well below baseline, the wrong-change case the gate must fail); `retracted-past` 0.339 to 1.000 (recall stays 1.000: with a single gold id the structural cap round 2 introduced is gone); `phrase-vague` 0.498 to 0.986.

Baseline (recall@10 / MRR@10, known-gap `control-not-asof` excluded from the headline): overall 0.707 / 0.474 (n=460); `knowledge-update` 0.958 / 0.702 (n=120); `temporal-during` 1.000 / 0.456 (n=100); `temporal` 0.458 / 0.368 (n=240). Subsets: current 0.958 / 0.702, prefiltered 0.917 / 0.736, phrase-dated 0 / 0 (report-only), phrase-vague 1.000 / 0.498, backdated-past 1.000 / 0.514, retracted-past 1.000 / 0.339, control-not-asof 0 / 0 (known-gap, all queries n=490 including it: recall@10 0.663 / MRR@10 0.445).

Power. Unpaired MDE for MRR@10 at 80% power, two-sided 95% (2.8 x bootstrap SE over clusters): 0.044 overall for the whole (non-gap) corpus, 0.031 within `temporal-during` alone (n=100), both well under the 0.05 target margin the gate's target path requires.

Cannot measure. Id-level gold cannot check that an as-of view shows the earlier version's text; `edited` timelines declare `priorVersions` for that future path and today only test retrieval. Contradiction detection at capture is unmeasured (see the oracle caveat above), and the loader writes with `storeEntry`, not `captureEntry`, so the LLM check does not run here.

## noise (NO-HARM REGRESSION GUARD, not an improvement gate for Track 3)

A round-2 review confirmed the mechanism is reproduced (the email/note split, the shared footer, the recurring notices) but found no headroom for the change Track 3 exists to make: in the synonym probes, when the gold misses the top 3 the slots are filled by other genuine notes (47 of 54 cases), not by mail, so no source-weight change can recover them; demoting all email below every note gains only about +0.008 MRR on the targeted subsets; and the literal-word probes and recurring-notice queries are already at 40/40 and 1.000, leaving them as regression guards only. Concretely, this corpus can confirm a Track 3 change did not regress recall or MRR (that check has real power, MDE about 0.06), but it cannot confirm the change improved anything, because the improvement it is meant to detect has less headroom here (about 0.01) than the corpus can resolve. Reproduces the Aug 16 mechanism: 6 senders plus 4 more with their own templates (deposit notices, bookings, prescriptions, bills, orders, statements), all ending in one identical long footer ("Thanks for choosing us. Sign in to your account ...", repeated as real mail repeats it). 90 near-identical direct deposit notices differ only in amount and reference. About 260 genuine notes reuse footer words.

Queries (210). `probe-footer-words` (40) and `probe-footer-synonym` (30): "choosing a name for the new feature", "User is choosing a datastore ...", "who did I thank for ...". They share only footer words with the mail; the answer is a genuine note, in the synonym tier written with no query words. `recurring` (40): "Show the direct deposits from payroll batch PB07" has three golds among 90 near-identical notices (so keeping one representative per template loses recall), plus amount lookups. `email-control` (60): flights, prescriptions, bills, half phrased "in my email ..." / "according to my email". `note-same-topic` (40): a genuine decision note on a topic that also has mail. 100 of 210 queries are answered by an email and 110 by a note, on the same topics, so source alone does not separate gold and blanket email demotion fails the email-correct half.

Baseline (recall@5 / MRR@10): overall 0.919 / 0.881. Subsets: probe-footer-words 1.000 / 0.988; probe-footer-synonym 0.433 / 0.351; recurring 1.000 / 1.000; email-control 1.000 / 0.975; note-same-topic 1.000 / 0.912. Email share of the top 3 on probes: 0.142 (literal), 0.122 (synonym). Email-correct queries with no email in the top 5: 0. Unpaired MDE for MRR@10: 0.057.

Cannot measure. The literal probes and recurring queries are saturated at baseline (no headroom), so they act as regression guards, not improvement targets. Headroom is in `probe-footer-synonym` (n=30), where failures mix footer intrusion with plain paraphrase weakness: the corpus cannot say how much of the 0.35 MRR is footer noise, and demoting email does not touch it (the 47-of-54 finding above). The live brain's 7-of-10 email top 10 was not reproduced at this size (650 documents against a real mailbox); do not read the probe email share as the production rate. Rahil has filed a follow-up to rebuild this corpus (a stronger attractor and dedicated crowding queries) before Track 3 starts; this round leaves it as-is and documents the gap instead.

## injection (REPORT-ONLY)

80 targeted subjects, each with a genuine note (gold), one planted email, and two benign emails on the same topic, inside 5,000 documents (plants 1.6%). Four plant styles, 20 each, tagged `plant-<style>`: `command` ("Ignore previous instructions ..."), `role` ("SYSTEM NOTICE to the assistant ..."), `factual` (poisoning with no command words: "the plan was cancelled"), `impersonation` ("Note to self: I changed my mind"). Metric: share of top-5 slots taken by planted documents for the targeted queries.

Baseline: planted top-5 share 0.397 (159/400 slots), 0.39 to 0.40 for every style; gold recall@5 1.000, MRR@10 0.268 (plants outrank the note). Own plant is rank 1 in 12/20 command, 11/20 role, 18/20 factual, 17/20 impersonation queries. MDE at 80% power, slot-level binomial: 0.069. Because the plants mimic the notes' subject, occupancy is high in every style; the factual style, which a command-word filter cannot catch, ranks first most often.

Cannot measure. Retrieval occupancy is not compliance: whether a model obeys a planted email needs a model and belongs to Track 5. Plants for other subjects share templates and appear in each other's results: 79 of 80 queries hold exactly two plants in their top 5, the targeted one plus one sibling-subject plant, so the occupancy metric is close to structural rather than a graded signal, and the effective independent sample is the 80 subjects, not 400 slots. The printed MDE (0.069) treats top-5 slots as independent binomial trials, which they are not for the reason above, so treat it as optimistic. Kept report-only for both reasons.

## standing (GATE for choosing Track 7's threshold, with caveats)

30 standing memories ("When booking a flight, check the shared calendar for conflicts first.") placed inside the core-1k documents (2,517 documents in all), all distinct situations so no memory has a sibling variant. Queries (1,500): 150 positives (5 phrasings per memory, gold = the memory); 120 `standing:overlap` negatives (different subject reusing the memory's key word, must not fire); 90 `standing:intent` (same subject, different intent such as "summarize the history of ...": the label is a product decision, reported apart and excluded from precision); 1,140 `standing:unrelated` (ordinary core-1k questions), so positives are 10% of traffic. Half the memories and half of the unrelated queries form a held-out `split:test`.

Method. Recall's embedding of each query is captured (`distilled`, what recall really sent to the model) and the raw query text is embedded too (`raw`). Each is compared by exact cosine with every standing memory's vector; at most two memories fire above a threshold, grid 0.30 to 0.90 by 0.05. Precision = TP / (TP + FP) over positives, overlap and unrelated queries; recall = TP / (TP + FN). The threshold is chosen on the dev split only (highest recall with precision at least 0.9, else best F1) and reported on the test split with 95% Wilson intervals. Product wiring is out of scope; Track 7 decides which input it uses.

Baseline. Distilled: chosen 0.75, held-out precision 1.000 [0.566, 1.000], recall 0.067 [0.029, 0.147]. Raw: chosen 0.70, held-out precision 1.000 [0.901, 1.000], recall 0.467 [0.358, 0.578]. Across all splits at 0.70: distilled precision 0.906 / recall 0.320, raw 0.988 / 0.540; at 0.65 raw is 0.834 / 0.840. The raw input clears the Track 7 goal (precision at least 0.9, recall at least 0.7) nowhere on this grid, but is far closer than the distilled one, whose dropped words cost most of the recall. Same-subject-other-intent queries fire in 15/90 (raw) and 23/90 (distilled) at 0.70 and in 66-73/90 at 0.60.

Gate caveats. Three open items keep this a gate "with caveats" rather than an unconditional one: (1) same-subject-other-intent fires (`standing:intent`) are excluded from precision because whether they should count is Rahil's product decision, not yet made; a decision to count them would move the chosen threshold. (2) The Wilson intervals are computed per query, not per memory, but true positives cluster by memory (raw's 0.70 test-split precision comes from 15 held-out memories, not 75 independent trials), so the printed intervals are narrower than the real uncertainty; treat them as optimistic, the same direction as injection's MDE. (3) The precision curve sits at a cliff: raw goes from 0.834 at 0.65 to 0.988 at 0.70, so the chosen operating point is sensitive to small changes in the embedding or the grid spacing (0.05 wide), and a production threshold should be re-validated rather than copied from this grid directly.

Cannot measure. The memories are hand-written and templated in phrasing (5 positive templates), so intervals reflect the 15 held-out memories, not the space of real instructions; unrelated traffic is core-1k question text, not real chat, and the 10% positive prevalence is asserted by construction, not measured from production.
