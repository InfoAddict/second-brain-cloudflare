# Synthetic 4.0 eval corpora

Four opt-in corpora, generated from seed `40891` (generators in `corpus/synthetic-*.ts`, SHA-256 data fingerprint in each spec). Every document is fictional. No account, live brain or Cloudflare API is used: the loader uses the production index write path over local D1, exact-cosine Vectorize and the pinned local embedding model. Default runs (`npm run eval:recall -- --variant baseline`) still select `core-1k` and never include these.

## Reproduce

Install with `npm ci`. For each corpus ID in `temporal noise injection`:

```sh
npm run eval:recall -- prepare --variant baseline --corpus ID
npm run eval:recall -- --variant baseline --corpus ID
```

For `standing`, use `--variant no-rerank` and add `--max-neurons 6000` to `prepare` (the byte-count estimate is about 4,100 production-equivalent neurons; nothing is billed, embeddings are local). `prepare` records content-addressed embeddings in `.eval-cache/replay/<corpus>.*.jsonl`; the second command is fully offline. Caches are not committed, as for public corpora: only the core cache is committed by repo convention, and these corpora never read or write it. Add `--json PATH` for a machine-readable report. `temporal` also works with `--compare no-rerank,baseline --target knowledge-update` (Track 2's current-state gate; `temporal-during` is report-only, not a target, see below); `noise` with `--target noise` (a no-harm check only, see below); the gate's cost check stays inconclusive on the sqlite backend, as everywhere.

A gate needs at least 200 queries and 30 clusters and the corpus must contain the failure it is meant to catch. Meeting the query and cluster floor is not enough: a corpus is a gate only where a wrong change is shown to fail it and a right change is shown to pass it. `temporal-during` meets the floor (225 queries, 190 clusters, MDE below) but not the second condition: a gate needs a real candidate, and Track 2's actual write path (C6) is not yet built, so it stays report-only alongside `temporal`, which round 3 already excluded for a related reason. `standing` is a threshold-selection gate, not a paired before/after gate: it has no baseline/candidate comparison, only a dev-chosen operating point scored on held-out data.

## temporal (GATE for `knowledge-update` only; `temporal-during` and `temporal`, including `control-not-asof`, are report-only)

What it measures. 280 timelines, each with a distinct pseudo-word subject ("Velmora studio lease", no numbered siblings), in ten shapes: `update` (35), `retro` (35, backdated notes and a recap written after the fact), `retracted` (30, a fact later withdrawn, then the withdrawal itself retracted), `edited` (20, a document edited after the as-of date), `retro-norecap` (30, backdated with no recap note, so gold is the newest document, created after the as-of date), `corrected` (30, wrong from the start, corrected later; gold is newest, forbidden is the original), `recap-only` (30, the recap is the only document valid at the as-of date and also the newest by creation), `silent` (30, a contradiction the loader never linked with an edge, so only staleness, not structure, can favor the new fact), `silent-fresh` (20, the same shape but "old" is under the 90-day staleness threshold, so gold stays "old"), `silent-true` (20, a lone state fact past the threshold with no rival at all, so gold is "old" and there is nothing to supersede it). Each timeline gets a current-state question (category `knowledge-update`, gold = the fact valid now, D-RET-restored where a belief was retracted). Its past questions split across three categories:

- `temporal` (report-only, 305 queries): `prefiltered` ("Where was X in April?" with a per-query `asOf`; the runner passes `before: asOf + 1`, so the newer fact is excluded and this only tests ranking among older documents), `phrase-dated` ("as of April 15, 2026", not pre-filtered, so the phrase parser is exercised), `phrase-relative-yesterday` (35 queries, `update` timelines only, "Where is X as of yesterday?"; see below), and `control-not-asof` (see below). **Do not target this category.** Before T-0089.2.5, the shipped parser turned a date-shaped phrase into a created-on-that-day filter that returned nothing, so `phrase-dated`'s baseline of 0 looked identical to a parser deleted entirely (round 3), and `control-not-asof` scored 0/0 outright (round 2). T-0089.2.5 fixed both misreadings (see below); `phrase-dated` is still not a target, because in 115 of 120 `update`/`retro`/`retracted`/`edited` queries tense wording alone ("was" vs "is now") already puts the old fact above the new one without any date parsing, so this subset still cannot distinguish a correct as-of implementation (which does not exist yet) from no implementation at all.
- `phrase-relative-yesterday` (T-0089.2.6 adversary round, MINOR item; 35 queries, report-only, no gate, no floor): "as of yesterday" through `parseTimePhrase`'s existing (pre-Track-2) `\byesterday\b` handler, which reads it as a created-at window filter rather than a Track 2 as-of read (`src/text/temporal.ts`'s own comment names this and defers the fix to "T2 lane C"). Lane C owns eval infrastructure, not the as-of implementation itself (Track A, not yet merged), so this names the case and measures it rather than gating a fix that cannot exist yet: the recorded baseline scores it **0.000 across all 35** (`rankedIds` empty), even though gold is in the pre-filter candidate pool -- "yesterday" narrows to a roughly 24-hour created-at window nothing in this corpus was created inside, hiding everything rather than just ranking it wrong. A future C6 implementation has a recorded number to be measured against.
- `temporal-during` (**report-only**: the round-4 mechanics below are fixed and proven against the recorded baseline directly, T-0089.2.6, but a gate needs C6's real write-path candidate, not yet built; 225 queries in 190 clusters): seven subsets, `during-before-change`/`during-after-change` (the `update` timeline, before and after its own supersede), `backdated-past`/`backdated-newest` (`retro` and `retro-norecap`), `retracted-past`/`corrected-backdated` (`retracted` and `corrected`), `recap-gold` (`recap-only`). `expectedAsOf` (and the identical `asOfParam`, the agent-supplied as-of path) record the date for the oracle and the runner. See "T-0089.2.6: the round-4 mechanics, fixed" below.
- `control-not-asof` (30 questions naming a place such as "the Aug 8 ... Cafe"; correct behaviour is ordinary retrieval, unaffected by a date parser). Fixed by T-0089.2.5 (see below); part of the ordinary `temporal` category, no tag; a corpus floor (`CorpusSpec.floors`, T-0089.2.6) enforces its MRR@10 >= 0.95 mechanically on every `--compare`.

### T-0089.2.6: the round-4 mechanics, fixed

Round 4 re-scored the recorded baseline through `evaluateGate` and found the gold was never the newest document of its timeline (so recency and anti-recency shortcuts both had something to grab), a category-level pass could hide a subset-level collapse, and the `retracted-past` gold conflicted with a retraction-semantics decision only Rahil could make. All three are now fixed structurally, not argued around:

1. **Newest-gold subsets.** Four new timeline shapes (`retro-norecap`, `corrected`, `recap-only`, `silent`) give `during-after-change`, `backdated-newest`, `corrected-backdated` and `recap-gold` gold that **is** the newest document, created after the as-of date, or both, so a "demote the newest" or "penalize created-after-T" shortcut fails somewhere, not just "passes because gold happened to be older everywhere." A structural cue-balance test (`corpus/synthetic.test.ts`) walks every round-4 cue (newest/oldest document, "Correction", "Looking back", " was ", "is now", an explicit date, created after T) and fails if a future corpus edit leaves one one-sided across every subset.
2. **Per-subset regression.** `gate.ts` now fails on a `(category, subset:<name>)` regression with at least 20 queries and 10 clusters (`subsetToleranceFloor` 0.05 or 1/n), reported as `GateResult.subsetRegressions`, for every corpus (not only temporal): the "boost 'was'" shortcut below now fails on `backdated-past` by name, where round 4 could only note that a category-level pass hid it.
3. **D-RET gold.** Rahil's 2026-09-27 decision (02-time-aware-truth.md, "Decision added 2026-09-27"): a retraction restores the superseded fact. `retracted-past`'s gold is `old` (actually-true), `bad` is `forbidden` (a new `GoldenQuery` field: `scoreQuery` cuts the ranking at the first forbidden id, so a belief ranked above gold zeroes the query rather than averaging away). `corrected-backdated` and the `knowledge-update` current questions carry the same `forbidden` shape for their own wrong originals.

**Proof, on the recorded baseline, through the real `evaluateGate`** (`temporal-gate-proof.test.ts`; transforms in `temporal-transforms.ts` re-rank the recorded report's own `rankedIds`, never an invented ranking, and read nothing but the report and the spec: "which documents are this query's own timeline" comes from the query's own `clusterKey`, production query metadata, never `gold`). **Every row below compares straight against the RECORDED BASELINE** (T-0089.2.6 adversary round; see "Adversary round" below for why rows 9, 12 and KU-2 no longer need a plan-oracle reference). `--target temporal-during` unless marked KU, all with `CorpusSpec.floors` and 10,000 bootstrap iterations:

### T-0089.2.6 adversary round: the recorded baseline itself was unrealistic

The Opus adversary (`temporal-gate-adversary.test.ts`, folded into the suite) found that rows 9, 12 and KU-2 above used to compare against a plan-oracle reference instead of the recorded baseline directly, because `retracted-past`, `corrected-backdated` and (what is now) `ku-retracted` scored near the floor in the *old* recorded baseline and so had nothing left to lose. That baseline was itself the bug: it was recorded with `bad` and `wrong` (the retracted beliefs) as ordinary, undeprecated notes, but release/v4 recall already excludes deprecated rows before ranking (`search.ts:872`), independent of any Track 2 code. Fixed:

1. **`bad` and `wrong` now carry `tags: ["status:deprecated"]`** and the recorded baseline was re-recorded against that state, the realistic pre-Track-2 production behaviour. Forbidden-above-gold on the baseline dropped from 29/30 (`retracted-past`), 22/30 (`corrected-backdated`) and 27/30 (`ku-corrected`) to **0/30 everywhere**, and `retracted-past`/`corrected-backdated`/`ku-corrected`/`ku-retracted` now score 1.000/1.000/1.000 (or 0.500 MRR for `retracted-past`, a legitimate, non-inflated as-of signal) instead of near zero -- real headroom a further-wrong transform can regress *from the baseline itself*.
2. **`CorpusSpec.floors` gained four D-RET floors** (`D_RET_FLOOR_RECALL10` = 0.9, per-scope MRR minimums below the honest baseline number but well above what a candidate that drops or mis-ranks gold would score): `temporal-during [subset:retracted-past]`, `temporal-during [subset:corrected-backdated]`, `knowledge-update [subset:ku-corrected]`, `knowledge-update [subset:ku-retracted]`. These are absolute bars, not deltas, so a D-RET-ignoring candidate fails against the recorded baseline directly regardless of what it gains elsewhere.
3. **A belief-time transform needs its own retrieval path back to a deprecated belief.** Once `bad`/`wrong` are correctly excluded from the default retrieved pool, a naive "promote the retracted belief to rank 1" (row 9) or "old stays closed by a belief" (KU-2, row 12) hypothesis has nothing left to act on through `ranked` alone. `oracleBeliefFirst` and `currentOracleNoRestore` now look the belief up through the query's own `clusterKey` (production query metadata, not gold, not `ranked`-membership), matching what a real belief-time-aware as-of path would need to do anyway: it must be able to see retracted rows the default path hides, to compute "what was believed at T" at all.
4. **`ku-silent` redesigned for real headroom, and KU-4 built.** The old `ku-silent` design scored 1.000 at baseline (no room for T-0089.2.3's stale-penalty target to show a win). The new "old" (a direct, un-hedged statement) vs. "new" (a hedged, unconfirmed secondhand report) pair, with no supersede edge at all (nothing structural to disambiguate), scores 0.933/0.967/0.745 at baseline; a `staleDemote` transform (an upper bound on a 0.9 staleness multiplier) reaches 0.917 MRR via `--target-subsets knowledge-update:ku-silent` (KU-4 above).
5. **Cross-timeline noise, found while re-proving the matrix.** `demoteNewest`, `dropOwnTimeline` and the belief-lookup transforms previously scoped "this query's own timeline" from an id-prefix over `ranked`, but two different timeline instances can retrieve into the *same* query's candidates when their generated wording embeds similarly (round 4's own `retro`/`recap` phrasing does this); a prefix or `ranked`-membership check alone cannot tell that apart from the query's real timeline. Scoping to the query's own `clusterKey` instead (exact, not a prefix guess) fixed it, and is also why row 6 no longer names `corrected-backdated`.

### T-0089.2.6 adversary round 2: the ku-silent stale gate could not fail

The Opus adversary (`temporal-gate-adversary-r2.test.ts`, folded into the suite) found `ku-silent` alone could not tell a right stale-penalty implementation from a wrong one: `staleDemote` (KU-4's candidate) never checked age at all, every one of the 30 `ku-silent` state rows was already past the 90-day threshold (so an age-blind penalty scores identically to an age-aware one), no gold anywhere in `knowledge-update` was a state fact that was stale AND still true (so a penalty's only possible harm, wrongly demoting a true fact, was unmeasurable), and the hedge/secondhand wording happened to sit only on `ku-silent`'s gold, so a bare "boost hedge wording" shortcut passed `--target-subsets knowledge-update:ku-silent` at +0.221 MRR, same as a real penalty. Fixed:

1. **`silent-fresh` (20 instances):** the same "old" (direct statement) vs. "new" (hedge/secondhand) pair as `ku-silent`, but "old" is created under 90 days before `EVAL_NOW`, so gold stays "old". An age-blind penalty (round 2's R1) demotes it anyway (regression); a hedge-boost shortcut (R2) promotes "new", which is not gold here, over it (regression too) -- the corpus now has a rival on both sides of the tag/wording confound.
2. **`silent-true` (20 instances):** a lone state fact, past the 90-day threshold, with no rival document in its own timeline at all. R4's concern ("no stale-but-still-true gold exists") now has 20 real instances; a penalty that demotes any old, tagged row regardless of whether anything actually contests it still has room to lose (baseline 1.000/1.000/1.000; nothing to gain, only to lose).
3. **`staleDemote` now checks age and a same-timeline rival**, via `STALE_THRESHOLD_DAYS` (90) and `timelineEntries` (the same `clusterKey`-based, gold-free lookup from round 1): a row is demoted only if it is a `volatility:state` row at least 90 days old AND its own timeline (via `clusterKey`, not gold) has more than one member. This correctly skips `silent-fresh`'s "old" (too young) and `silent-true`'s "old" (no rival), while still demoting the original `ku-silent`'s "old" exactly as before -- KU-4's improvement number is unchanged (0.745 to 0.917 MRR).
4. **KU-1 retargeted.** Adding `silent-fresh`/`silent-true` (40 more knowledge-update queries with no supersede edge, so `planOracle` cannot move them) diluted the category-wide average below its 0.05 margin; KU-1 now proves its real, provable win directly on `subset:current` (mrr10 +0.081, lo +0.052) via `--target-subsets`, the same pattern KU-4 already used.

R2's adversary probes (R1, R2, R3, R4) all pass with these fixes: R1 (age-blind, ignores 90-day rule) and R2 (hedge-boost shortcut) now correctly fail to pass the gate (subset regressions on `silent-fresh`/`silent-true`); R3 (plain recency) still correctly fails; R4 confirms 40 stale-and-true gold rows now exist. The fixed `staleDemote` itself still passes.

T-0089.2.5: `control-not-asof` was excluded, then fixed (history). Before this fix, the shipped parser misread these month-day names as dates, so the baseline itself scored 0/0. A delta-from-baseline rule compares a candidate against that same 0, so a worse candidate parser could not show as a regression: both scored 0, with nothing left to fall to. Concretely, a parser that read every month-day-shaped string as an as-of date got 40% of these controls right (0.60 MRR) against a correct parser's 1.00, yet a delta-based rule still called 0.60 an improvement over the 0 baseline (asserted in `temporal-gate.test.ts`, kept as a fixture: the "misreading" candidate passes `--target-gaps temporal-month-day-controls` exactly as the "correct" one does). **The mechanical target-gaps rule alone cannot tell those two apart; `gate.ts` was not changed to try.** Instead, T-0089.2.5 (filed on the board, parent T-0089.2) landed first in Track 2, fixing `src/text/temporal.ts` so a month-day match followed by a proper noun (a name, not a date) and an "as of" phrase are no longer read as a created-on-that-day filter. Both acceptance parts, mechanical and manual, held before the tag was removed:
1. `npm run eval:recall -- --compare no-rerank,baseline --corpus temporal --target-gaps temporal-month-day-controls` reports a passing `improvement` rule (the delta on this particular pair is 0, since both compared variants share the same, already-fixed code; the printed rule still reports pass because the pair's own overall reranking gain clears the margin, and no regression rule fires); and
2. the printed `known gaps` row for `gap:temporal-month-day-controls` reached **MRR@10 >= 0.95** (it reached 1.000, printed as "acceptance floor MRR@10 0.95 (T-0089.2.5): met"), confirmed by comparing a real embedding run of the pre-fix parser (MRR@10 0.000 on this row) against the same run of the post-fix parser (MRR@10 1.000), both `--variant baseline --corpus temporal`.

With both parts held, the `gap:temporal-month-day-controls` tag was removed from the 30 control queries in `corpus/synthetic-temporal.ts`; they now rejoin the ordinary `temporal` category's regression rule (report-only, as above) and protect every later temporal change from the same class of misreading. `MONTH_DAY_CONTROL_GAP_TAG` and `MONTH_DAY_CONTROL_ACCEPTANCE_MRR` remain in `corpus/synthetic-temporal.ts`, no longer applied to any query, kept only as pinned fixture values for `temporal-gate.test.ts`'s and `synthetic-acceptance.test.ts`'s gate-mechanics tests and for this history.

Data model (`corpus/types.ts`). `CorpusEntry` gains `updatedAt`, `validFrom`, `validUntil`, `retractedAt`, `priorVersions`; supersession is a `supersedes` edge (newer to older). The loader writes `updated_at` and the edges today. `applySupportedTemporalMetadata` (`corpus/loader.ts`) writes `valid_from`/`valid_until` only when the entries table has those columns (none yet), and `loadCorpus` takes a `temporalMetadata` writer as the extension point for Track 2's write path (C6, waiting on A3/A5). `GoldenQuery` gains `expectedAsOf` (the oracle's question time), `asOfParam` (every `temporal-during` query; the runner passes it as `asOf` through a forward-compatible spread, inert until B3 adds the param to `recallEntries`) and `forbidden` (ids that must not rank above gold). Documents are dated at noon UTC so the local-time date parser gives the same answer in every timezone from UTC-11 to UTC+11.

`retracted-past` and `corrected-backdated` gold, settled (D-RET, Rahil 2026-09-27). "Where was X during July/February?" after a move (or an original claim) was later corrected. Gold is the actually-true document only (`old`, `correction`), grade 2; the wrong belief (`bad`, `wrong`) is `forbidden`, not a second gold: `scoreQuery` cuts the ranking at the first forbidden id, so a system that ranks the belief first scores 0, not the same as one that ranks the actually-true answer first (round 3's original concern, now enforced mechanically rather than by grade alone, since `recallAtK`/`mrrAtK` still ignore grade). `bad` and `wrong` declare an empty validity window (`validUntil` equal to `validFrom`, half-open, never valid), meaning they were never actually true, while `retractedAt` separately records when the correction was learned, and (T-0089.2.6 adversary round) both carry `tags: ["status:deprecated"]`, the realistic pre-Track-2 production state: release/v4 recall already excludes deprecated rows before ranking (`search.ts:872`), independent of Track 2. `synthetic-report.ts`'s "forbidden above gold" line (generalized from the old retracted-past-only belief-time diagnostic) prints how often the belief still outranks gold in the raw ranking, per subset: today (pre-Track-2, with that exclusion in place), **0/30 everywhere** -- `retracted-past`, `corrected-backdated`, `ku-corrected`, `ku-retracted`. Not gated (`scoreQuery` already prices it into `mrr10`/`recall10`); a diagnostic of where it is still happening.

Oracle (`temporal-oracle.ts`, printed in the report). From the recorded rankings alone it simulates (a) supersession applied: keeps documents valid at the question date, with a retracted belief (`retractedAt` set) placed below them rather than dropped, since it was actually told and a belief-time system could still surface it; (b) recency only: reorder by creation time, which the backdated recap defeats. This is an upper bound on what a correct implementation can do to today's ranking under the corpus's own (actually-true) validity data, not a prediction of Track 2's contradiction detector: the loader writes validity exactly as the corpus declares it, so the ceiling assumes perfect contradiction detection at capture. Baseline `knowledge-update` MRR@10 is 0.817 (n=280); supersession applied 0.861; a plain recency reorder falls to 0.201. `silent-fresh`/`silent-true` carry no supersede edge (same as `silent`/`ku-silent`), so supersession leaves them, `ku-corrected` and `ku-retracted` unchanged; only `current` moves (0.748 to 0.829), which is why the category-wide gain is now below the target margin and KU-1 targets `current` directly. On `temporal-during`, baseline 0.773; supersession applied 0.998; recency-only falls to 0.280. `retracted-past` (a forbidden id, the subset with the most room) is 0.500 at baseline, reaching 1.000 under supersession (recency falls to 0.128); `corrected-backdated` and `ku-corrected` are already at the 1.000 ceiling post-deprecation-fix, so supersession has nothing left to gain there (recency falls to 0.111 and 0.127). `control-not-asof` (no timeline of its own to defend): 1.000 baseline MRR falls to 0.667 under supersession (which has nothing to keep valid there) and to 0.320 under a plain recency reorder (recall stays 1.000 either way); not gated, printed for completeness.

Baseline, after T-0089.2.6's adversary round 2 (recall@10 / MRR@10; retracted rows deprecated, the realistic pre-Track-2 production state; no known gaps remain in this corpus): overall 0.867 / 0.726 (n=810); `knowledge-update` 0.979 / 0.817 (n=280); `temporal-during` 1.000 / 0.773 (n=225); `temporal` 0.666 / 0.608 (n=305). Subsets: current 0.980 / 0.748 (n=150), ku-corrected 1.000 / 1.000 (n=30), ku-retracted 1.000 / 1.000 (n=30), ku-silent 0.900 / 0.705 (n=30), ku-silent-fresh 1.000 / 0.775 (n=20), ku-silent-true 1.000 / 1.000 (n=20), prefiltered 0.733 / 0.713 (n=120), phrase-dated 0.708 / 0.583 (n=120, report-only), phrase-relative-yesterday 0.000 / 0.000 (n=35, report-only, see above), control-not-asof 1.000 / 1.000 (n=30, T-0089.2.5's floor met), during-before-change 1.000 / 0.567 (n=35), during-after-change 1.000 / 0.895 (n=35), backdated-past 1.000 / 0.510 (n=35), backdated-newest 1.000 / 1.000 (n=30), retracted-past 1.000 / 0.500 (n=30), corrected-backdated 1.000 / 1.000 (n=30), recap-gold 1.000 / 1.000 (n=30). Recorded (not locked) at `test/eval/data/recorded/temporal.bge-small-en-v1.5.json`; re-record with `npm run eval:recall -- prepare --variant baseline --corpus temporal` (needed whenever new query text is added) then `npm run eval:recall -- --variant baseline --corpus temporal --json <scratch path>` and copy to that path (the CLI refuses to write `--json` directly under `test/eval/data/`, which only lock writes may touch) whenever the corpus's `dataFingerprint` changes (`recorded-baseline.test.ts` names the exact command and fails first).

Power. Unpaired MDE for MRR@10, one-sided at 80% power (2.8 x bootstrap SE over clusters; the gate's actual decision only reads the lower tail of the two-sided 95% CI the bootstrap builds, see `stats.ts`): 0.059 overall for the whole corpus (n=810, no known gaps to exclude). Comfortably under the 0.05 target margin a gate's target path would use.

## noise (NO-HARM REGRESSION GUARD, not an improvement gate for Track 3)

A round-2 review confirmed the mechanism is reproduced (the email/note split, the shared footer, the recurring notices) but found no headroom for the change Track 3 exists to make: in the synonym probes, when the gold misses the top 3 the slots are filled by other genuine notes (47 of 54 cases), not by mail, so no source-weight change can recover them; demoting all email below every note gains only about +0.008 MRR on the targeted subsets; and the literal-word probes and recurring-notice queries are already at 40/40 and 1.000, leaving them as regression guards only. Concretely, this corpus can confirm a Track 3 change did not regress recall or MRR (that check has real power, MDE about 0.06), but it cannot confirm the change improved anything, because the improvement it is meant to detect has less headroom here (about 0.01) than the corpus can resolve. Reproduces the Aug 16 mechanism: 6 senders plus 4 more with their own templates (deposit notices, bookings, prescriptions, bills, orders, statements), all ending in one identical long footer ("Thanks for choosing us. Sign in to your account ...", repeated as real mail repeats it). 90 near-identical direct deposit notices differ only in amount and reference. About 260 genuine notes reuse footer words.

Queries (210). `probe-footer-words` (40) and `probe-footer-synonym` (30): "choosing a name for the new feature", "User is choosing a datastore ...", "who did I thank for ...". They share only footer words with the mail; the answer is a genuine note, in the synonym tier written with no query words. `recurring` (40): "Show the direct deposits from payroll batch PB07" has three golds among 90 near-identical notices (so keeping one representative per template loses recall), plus amount lookups. `email-control` (60): flights, prescriptions, bills, half phrased "in my email ..." / "according to my email". `note-same-topic` (40): a genuine decision note on a topic that also has mail. 100 of 210 queries are answered by an email and 110 by a note, on the same topics, so source alone does not separate gold and blanket email demotion fails the email-correct half.

Baseline (recall@5 / MRR@10): overall 0.919 / 0.881. Subsets: probe-footer-words 1.000 / 0.988; probe-footer-synonym 0.433 / 0.351; recurring 1.000 / 1.000; email-control 1.000 / 0.975; note-same-topic 1.000 / 0.912. Email share of the top 3 on probes: 0.142 (literal), 0.122 (synonym). Email-correct queries with no email in the top 5: 0. Unpaired MDE for MRR@10: 0.057.

Cannot measure. The literal probes and recurring queries are saturated at baseline (no headroom), so they act as regression guards, not improvement targets. Headroom is in `probe-footer-synonym` (n=30), where failures mix footer intrusion with plain paraphrase weakness: the corpus cannot say how much of the 0.35 MRR is footer noise, and demoting email does not touch it (the 47-of-54 finding above). The live brain's 7-of-10 email top 10 was not reproduced at this size (650 documents against a real mailbox); do not read the probe email share as the production rate. Rahil has filed a follow-up to rebuild this corpus (a stronger attractor and dedicated crowding queries) before Track 3 starts; this round leaves it as-is and documents the gap instead.

## injection (REPORT-ONLY)

80 targeted subjects, each with a genuine note (gold), one planted email, and two benign emails on the same topic, inside 5,000 documents (plants 1.6%). Four plant styles, 20 each, tagged `plant-<style>`: `command` ("Ignore previous instructions ..."), `role` ("SYSTEM NOTICE to the assistant ..."), `factual` (poisoning with no command words: "the plan was cancelled"), `impersonation` ("Note to self: I changed my mind"). Metric: share of top-5 slots taken by planted documents for the targeted queries.

Baseline: planted top-5 share 0.397 (159/400 slots), 0.39 to 0.40 for every style; gold recall@5 1.000, MRR@10 0.268 (plants outrank the note). Own plant is rank 1 in 12/20 command, 11/20 role, 18/20 factual, 17/20 impersonation queries. MDE at 80% power, slot-level binomial: 0.069. Because the plants mimic the notes' subject, occupancy is high in every style; the factual style, which a command-word filter cannot catch, ranks first most often.

Cannot measure. Retrieval occupancy is not compliance: whether a model obeys a planted email needs a model and belongs to Track 5. Plants for other subjects share templates and appear in each other's results: 79 of 80 queries hold exactly two plants in their top 5, the targeted one plus one sibling-subject plant, so the occupancy metric is close to structural rather than a graded signal, and the effective independent sample is the 80 subjects, not 400 slots. The printed MDE (0.069) treats top-5 slots as independent binomial trials, which they are not for the reason above, so treat it as optimistic. Kept report-only for both reasons.

## standing (GATE for choosing Track 7's threshold, with caveats)

30 standing memories ("When booking a flight, check the shared calendar for conflicts first.") placed inside the core-1k documents (2,517 documents in all), all distinct situations so no memory has a sibling variant. Queries (1,500): 150 positives (5 phrasings per memory, gold = the memory); 120 `standing:overlap` negatives (different subject reusing the memory's key word, must not fire); 90 `standing:intent` (same subject, different intent such as "summarize the history of ...": the label is a product decision, reported apart and excluded from precision); 1,140 `standing:unrelated` (ordinary core-1k questions), so positives are 10% of traffic. Half the memories and half of the unrelated queries form a held-out `split:test`.

Method. Recall's embedding of each query is captured (`distilled`, what recall really sent to the model) and the raw query text is embedded too (`raw`). Each is compared by exact cosine with every standing memory's vector; at most two memories fire above a threshold, grid 0.30 to 0.90 by 0.05. Precision = TP / (TP + FP) over positives, overlap and unrelated queries; recall = TP / (TP + FN). The threshold is chosen on the dev split only (highest recall with precision at least 0.9, else best F1) and reported on the test split with 95% Wilson intervals. Product wiring is out of scope; Track 7 decides which input it uses.

Baseline. Distilled: chosen 0.75, held-out precision 1.000 [0.566, 1.000], recall 0.067 [0.029, 0.147]. Raw: chosen 0.70, held-out precision 1.000 [0.901, 1.000], recall 0.467 [0.358, 0.578]. Across all splits at 0.70: distilled precision 0.906 / recall 0.320, raw 0.988 / 0.540; at 0.65 raw is 0.834 / 0.840. The raw input clears the Track 7 goal (precision at least 0.9, recall at least 0.7) nowhere on this grid, but is far closer than the distilled one, whose dropped words cost most of the recall. Same-subject-other-intent queries fire in 15/90 (raw) and 23/90 (distilled) at 0.70 and in 66-73/90 at 0.60.

Gate caveats. Three open items keep this a gate "with caveats" rather than an unconditional one: (1) same-subject-other-intent fires (`standing:intent`) are excluded from precision because whether they should count is Rahil's product decision, not yet made; a decision to count them would move the chosen threshold. (2) The Wilson intervals are computed per query, not per memory, but true positives cluster by memory (raw's 0.70 test-split precision comes from 15 held-out memories, not 75 independent trials), so the printed intervals are narrower than the real uncertainty; treat them as optimistic, the same direction as injection's MDE. (3) The precision curve sits at a cliff: raw goes from 0.834 at 0.65 to 0.988 at 0.70, so the chosen operating point is sensitive to small changes in the embedding or the grid spacing (0.05 wide), and a production threshold should be re-validated rather than copied from this grid directly.

Cannot measure. The memories are hand-written and templated in phrasing (5 positive templates), so intervals reflect the 15 held-out memories, not the space of real instructions; unrelated traffic is core-1k question text, not real chat, and the 10% positive prevalence is asserted by construction, not measured from production.
